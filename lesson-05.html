פקודות מותאמות אישית ו‑Skills

כל בקשה שמצאתם את עצמכם מקלידים בפעם השלישית — ראויה להפוך לפקודה של מילה אחת. בפרק הזה נבנה פקודות Slash משלנו, ואז נעלה שלב ל‑Skills: חבילות ידע ש‑Claude שולף בעצמו ברגע הנכון.

מה נלמד בפרק

  • יצירת פקודות Slash אישיות עם פרמטרים
  • ההבדל בין פקודה (אתם מפעילים) ל‑Skill (המודל מפעיל)
  • בניית Skill מלא עם קובצי עזר
  • ארגון ושיתוף עם הצוות

פקודות Slash מותאמות

פקודה מותאמת היא פשוט קובץ Markdown בתיקייה .claude/commands/ בפרויקט. שם הקובץ הוא שם הפקודה, והתוכן הוא הפרומפט שיישלח כשתקראו לה. ניצור אחת:

.claude/commands/check.mdבצע בדיקת איכות מלאה על השינויים הנוכחיים:
1. הרץ את הטסטים ואת ה-lint
2. עבור על ה-diff וחפש: באגים, כפילויות קוד, שמות לא ברורים
3. ודא שאין סודות (מפתחות, סיסמאות) בקוד
4. סכם ממצאים בטבלה: חומרה, קובץ, בעיה, תיקון מוצע
אל תתקן כלום בשלב הזה - רק דווח.

זהו. מעכשיו בכל שיחה: /check — וכל התהליך רץ.

פרמטרים עם $ARGUMENTS

המחרוזת $ARGUMENTS בקובץ מוחלפת במה שנכתב אחרי שם הפקודה:

.claude/commands/fix-issue.mdקרא את issue מספר $ARGUMENTS בעזרת gh issue view.
הבן את הבעיה, מצא את הקוד הרלוונטי, תקן, הוסף טסט שמוכיח את התיקון,
והצג לי סיכום לפני קומיט.

שימוש: /fix-issue 123. ככה הופכים תהליך שלם — מקריאת התקלה ועד טסט — לפקודה אחת.

✅ פקודות אישיות גלובליות פקודות ששמות ב‑~/.claude/commands/ זמינות בכל הפרויקטים שלכם. פקודות ב‑.claude/commands/ של הפרויקט נכנסות ל‑git ומשותפות לכל הצוות — ספריית תהליכים צוותית.

Skills — ידע שנשלף לבד

פקודת Slash אתם מפעילים ידנית. Skill הוא ידע ש‑Claude מפעיל בעצמו כשהוא מזהה שהמשימה מתאימה. כל Skill הוא תיקייה עם קובץ SKILL.md, שמתחיל בכותרת מטא־נתונים:

.claude/skills/hebrew-ui/SKILL.md---
name: hebrew-ui
description: כללים לבניית ממשקים בעברית עם RTL תקין. השתמש בכל
  פעם שנוצרים או נערכים רכיבי UI עם טקסט עברי.
---

# בניית UI בעברית

## כללי חובה
- על אלמנט השורש: dir="rtl" ו-lang="he"
- להשתמש ב-margin-inline-start ולא ב-margin-left
  (וכך לכל מאפייני צד: padding-inline, inset-inline, text-align: start)
- מספרים וקוד נשארים LTR: לעטוף ב-dir="ltr"
- אייקוני חצים "קדימה/אחורה" מתהפכים ב-RTL - לבדוק כיוון

## בדיקות לפני סיום
1. אין גלילה אופקית בעמוד
2. סימני פיסוק בסוף משפט עברי מוצגים נכון
3. שדות טלפון/אימייל מיושרים LTR בתוך טופס RTL

איך זה עובד? בתחילת שיחה Claude רואה רק את ה‑name וה‑description של כל ה‑Skills. כשמגיעה משימת UI בעברית — הוא טוען את הקובץ המלא לבד. לכן ה‑description הוא הכול: הוא חייב לתאר בבירור מתי להשתמש ב‑Skill.

Skill עם קבצים נלווים

Skill יכול להכיל גם סקריפטים, תבניות וקובצי עזר לצד ה‑SKILL.md:

.claude/skills/deploy-checklist/
├── SKILL.md          ← ההוראות + מתי להפעיל
├── checklist.md      ← רשימת בדיקות מפורטת
└── verify.sh         ← סקריפט שה-Skill מנחה להריץ

ב‑SKILL.md כותבים למשל: "לפני deploy הרץ את verify.sh ועבור על checklist.md סעיף־סעיף". כך אורזים תהליך שלם — ידע, אוטומציה ובקרה — בחבילה אחת שהמודל יודע להפעיל.

💡 מתי פקודה ומתי Skill? פקודה — כשאתם רוצים שליטה: "עכשיו תעשה X" (‏/check, /fix-issue).
Skill — כשאתם רוצים שהידע יחול אוטומטית בכל פעם שהוא רלוונטי, בלי שתזכרו לבקש (כללי RTL, סטנדרטים של API, נהלי deploy).

תרגילים

תרגיל 5.1 הפקודה הראשונה שלכם

חשבו על בקשה שכבר כתבתם ל‑Claude יותר מפעם אחת, וצרו ממנה פקודה ב‑.claude/commands/. אין רעיון? צרו /explain — פקודה שמסבירה קובץ: מקבלת נתיב כ‑$ARGUMENTS ומחזירה הסבר מובנה: תפקיד, תלויות, ונקודות תורפה.

פתרון לדוגמה 
.claude/commands/explain.mdקרא את הקובץ $ARGUMENTS והסבר:
1. מה תפקידו במשפט אחד
2. מה ה-API הציבורי שלו (פונקציות/מחלקות עיקריות)
3. במי הוא תלוי ומי תלוי בו
4. נקודת התורפה הכי מסוכנת בו
כתוב בעברית, קצר וברור.
תרגיל 5.2 Skill שנטען לבד

צרו Skill בשם commit-style שמגדיר סגנון הודעות קומיט (למשל: תבנית type: summary, גוף שמסביר "למה" ולא "מה"). ה‑description צריך לגרום לו להיטען בכל פעם שנוצר קומיט. בדקו: פתחו שיחה חדשה, עשו שינוי, בקשו קומיט — ובדקו שהסגנון נאכף בלי שהזכרתם אותו.

נקודת מפתח

אם ה‑Skill לא נטען — הבעיה כמעט תמיד ב‑description. נסחו אותו כתשובה לשאלה "מתי להשתמש?": Use when creating git commits or writing commit messages. תיאור כללי מדי ("כללי סגנון") לא ייתן למודל סיבה לשלוף אותו.

תרגיל 5.3 ספריית צוות

בנו "ערכת פרויקט" שלמה: לפחות שתי פקודות (/check, /new-feature) ו‑Skill אחד, הכניסו הכול ל‑git עם קומיט מסודר. בונוס: בקשו מ‑Claude עצמו לבנות את הפקודות — תארו לו את התהליך שלכם והוא ינסח את הקבצים.

למה זה שווה את המאמץ

כש‑.claude/ נמצא בריפו, כל חבר צוות (וכל סוכן אוטונומי שירוץ על הריפו בעתיד!) מקבל את אותם תהליכים בדיוק. זו תשתית שתשרת אתכם ישירות בפרקים 9–10.

סיכום הפרק

  • פקודה מותאמת = קובץ Markdown ב‑.claude/commands/, עם $ARGUMENTS לפרמטרים
  • Skill = תיקייה עם SKILL.md ש‑Claude טוען לבד לפי ה‑description
  • פקודה מפעילים אתם; Skill מפעיל המודל — לכל אחד תפקיד
  • הכול נכנס ל‑git ומשותף לצוות ולסוכנים עתידיים
