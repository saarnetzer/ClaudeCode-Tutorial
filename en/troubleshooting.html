When something doesn't work

Before you give up: most Claude Code problems are one of five, and all of them have a short fix. This page is ordered as a check sequence — start at the top and stop as soon as you've found it. Bookmark it; it will save you an evening.

The check order: three commands that solve most cases

Don't guess. These three tell you what's broken, in this order:

#CommandWhat it tells you
1claude --versionWhether the install is sound at all. Run it in a new terminal window.
2claude doctorDiagnostics from your shell, even when the tool won't start: broken settings files, search status, permission problems.
3/doctorA full checkup from inside a session — and it proposes fixes, asking you before it touches anything.
✅ The trump card: safe mode Suspect something you added is breaking it — a hook, an MCP server, a plugin, a Skill? Run: 
claude --safe-mode
That starts a session with no CLAUDE.md, no Skills, no plugins, no hooks, no MCP servers and no custom commands. Login, model and built-in tools work as normal. If the problem disappears, it's in your configuration — and now you only have to narrow down which part. It's the single most useful check on this page.

1. "command not found: claude"

The most common problem, and usually not really an install problem — the tool is there, your system just doesn't know where. First, close your terminal and open a new one; a PATH change only loads in a new window. Still nothing?

Check the file is actually there

macOS / Linuxls -la ~/.local/bin/claude
Windows (PowerShell)Test-Path "$env:USERPROFILE\.local\bin\claude.exe"

If the file isn't there, the install didn't complete — go back to Lesson 1 and run it again. If it is there, the problem is your PATH:

Add it to your PATH

macOS (zsh — the default)echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
Linux (bash)echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
Windows (PowerShell, then open a new terminal)$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
💡 Three traps worth knowing (1) If you're in a terminal inside a code editor, it inherits PATH from the editor — so you have to restart the editor itself, not just the terminal. (2) Not sure which shell you're running? echo $0 tells you, so you edit the right file. (3) The VS Code extension does not put claude on your PATH — you need the standalone install too.

Two installs fighting each other?

which -a claude

Several lines means several installs — keep one. To remove the others: npm uninstall -g @anthropic-ai/claude-code, rm -rf ~/.claude/local, brew uninstall --cask claude-code or winget uninstall Anthropic.ClaudeCode, depending on how you installed.

2. The install itself fails

What you seeWhat it means and what to do
403 or syntax error near unexpected token '<'You got a web page instead of a script — usually a firewall or corporate proxy. Test with curl -sI https://downloads.claude.ai/claude-code-releases/latest (expect 200). Work around it with Homebrew or WinGet.
EACCES / permission deniedNo write permission. sudo mkdir -p ~/.local/bin then sudo chown -R $(whoami) ~/.local. If you installed via npm and hit permission errors, switch to the native installer — and never run npm with sudo.
Killed (Linux)Out of memory. The install needs about half a gigabyte free, and the tool itself 4 GB. Add a swap file or use a bigger machine.
Certificate errors / unable to get local issuer certificateOn Ubuntu: sudo apt-get install ca-certificates. Behind a corporate proxy, ask IT for a PEM of the root certificate and point CURL_CA_BUNDLE and NODE_EXTRA_CA_CERTS at it.
'irm' is not recognized / an error about &&You're in the wrong window. irm is PowerShell; the && command is CMD. See Lesson 1.
⚠️ Windows: two errors of its own "requires either Git for Windows or PowerShell" — install Git for Windows and choose the option to add it to PATH.
"does not support 32-bit Windows" — you opened Windows PowerShell (x86) by mistake. Open the regular one.

3. Login problems

The reset that fixes most login cases: /logout, close Claude Code completely, run claude, and sign in again.

What you seeWhat to do
403 Request not allowedCheck your subscription is active at claude.ai/settings. On Console, check your role includes Claude Code access.
This organization has been disabledAlmost always: an old ANTHROPIC_API_KEY environment variable overriding your subscription. Run unset ANTHROPIC_API_KEY and delete the line from your shell file. Confirm with /status.
The browser won't open (SSH, WSL, a container)Press c to copy the URL, open it in your local browser, and paste the code back into the terminal.
"That doesn't look like the full code"Copy the whole code including the #, and paste it quickly — it expires.
The token keeps expiringCheck your system clock. Token validation depends on it.

4. An MCP server won't connect

/mcp shows the status of every server. The three common causes, in order of frequency:

  • You never approved it. A server defined in a project's .mcp.json needs a one-time approval. If you dismissed the prompt: claude mcp reset-project-choices, restart, approve.
  • A relative path. This is the big trap: paths in .mcp.json resolve relative to where you launched Claude, not relative to the file. For local scripts, always use a full path.
  • The file is in the wrong place. It must be called .mcp.json and sit at the repo root — not inside .claude/. And servers you write inside settings.json are simply ignored.

Connected but offering no tools? Choose Reconnect inside /mcp. If that doesn't help, run claude --debug=mcp and read the log in ~/.claude/debug/.

5. Hooks don't fire, Skills don't load

These two feel mysterious because they fail silently — there's no error message. The first check is always whether the thing loaded at all: /hooks and /skills.

A hook that doesn't fire

  • The matcher must be a string, not an array.
  • Tool names are capitalized: Bash, Edit, Write, Read. "bash" matches nothing.
  • For several tools use a pipe: "Edit|Write".
  • A misspelled tool name matches nothing — silently.
  • The configuration must sit under the "hooks" key in settings.json. There is no separate hooks file.

To watch evaluation live: claude --debug, then trigger the tool.

A Skill that doesn't load

  • The layout must be .claude/skills/name/SKILL.md — a folder with a file inside, not .claude/skills/name.md.
  • The description has to match how you actually phrase requests — it's the model's only way to decide to load it. See Lesson 5.
  • A "user-only" badge in the list means Claude won't invoke it by itself. Check for disable-model-invocation: true in the frontmatter.

CLAUDE.md being ignored

Run /context — it shows what actually loaded. A CLAUDE.md in a subdirectory only loads when you work in that area. And for settings: settings.local.json beats the project's, which beats your personal one.

6. Slowness, memory, and hangs

SymptomWhat to do
Slow, or the session "forgets"The context window is full. /compact at a stopping point, /clear between tasks, /context to see what's taking up room. Lesson 4.
High memory or CPURestart between big tasks. Check whether it's something you added with claude --safe-mode.
A command is stuck and unresponsiveCtrl+C. If that won't do it, close the terminal and run claude --resume in the same folder. Your conversation is kept.
Slow or incomplete searchInstall ripgrep on your system. On WSL, keep the project under /home/ rather than /mnt/c/ — it makes a dramatic difference.

When nothing helps

At this point, let Claude diagnose itself: the /debug command turns on detailed logging and then asks it to read the log and explain what happened. The logs live in ~/.claude/debug/.

And if it looks like a genuine bug, /bug sends a report to Anthropic, with a consent screen showing you exactly what will be sent before anything leaves.
