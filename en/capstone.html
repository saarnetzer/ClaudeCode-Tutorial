Capstone project

Build something real — and get scored on it

A good course isn't measured by how many lessons you read, but by what you can build afterwards. The capstone is the proof: an agent or an agent squad running on something real of yours — reviewed against clear criteria.

What to build

Pick one track — both are scored identically:

🤖 Track A: an autonomous agent

A single agent that runs on a schedule or with one command and performs a real task end to end: dependency updates, dead-code cleanup, improving test coverage, a periodic report.

Based on Lesson 11, exercise 11.3

👥 Track B: an agent squad

Three or more roles with an orchestrator, shared memory and deliverable contracts — in your own domain: development, marketing, data, operations or support.

Based on Lesson 12 and Lesson 13

⚠️ One hard requirement The project must run on something real of yours — a repo, data or a process you actually work with. A toy project will pass the technical review and miss the entire point.

How you're scored

The criteria are no surprise — they're the five autonomy principles from Lesson 11, weighted:

#CriterionWhat's actually checkedWeight
1Feedback loopThe agent has an objective way to know it succeeded — and actually runs it25%
2Boundaries in codeNarrow allowedTools, deny rules, blocking hooks, readonly MCP access25%
3Quantitative brakesA turn cap, cost monitoring, a timeout15%
4External memoryWork in slices, a state file, a commit per stage15%
5Human at decision pointsThe output passes approval, alerts on anomalies, clear who approves what20%

The decisive rule: the distinction between declared and enforced. An instruction in CLAUDE.md is a request; a deny rule or a hook is a mechanism. Full marks on criterion 2 are awarded only for enforcement.

Step 1: check yourself — with an agent

Before submitting, let an examiner agent go over your work. It checks all five criteria, looks for evidence in the code, and returns a report with a score and the three most important fixes:

# 1. Download the examiner into your project
#    (link below — save it in .claude/agents/)

# 2. In your project, ask Claude:
have course-examiner review this project and give me a score

⬇️ Download the examiner agent (English) · גרסה עברית

✅ Why this works The examiner is defined with read-only permissions and an explicit instruction not to flatter — exactly the principles you learned in Lesson 8. It's also a live demonstration: an agent reviewing an agent's work. Got a low score? Fix and run it again. That's the loop.

Step 2: submit for review

Submitting is entirely optional — but it's what turns an exercise into a deliverable. Two ways:

  1. Peer review and feedback: open a capstone submission — a short description, a link to the repo (or screenshots if it's private), and the examiner's report. You'll get human feedback.
  2. For yourself only: save the examiner's report in the project as EXAM_REPORT.md and run it again in a month. Comparing the two reports is the real measure of your progress.
💡 A free GitHub account is required Submissions open as an issue on GitHub. No account? A two-minute setup guide. Don't want one? Option 2 stands on its own.

Step 3: the certificate

Once you've marked all 13 lessons complete, the certificate button appears on the home page. It's generated in your browser with the name you choose — and if you also passed the examiner, mention the score when you share it. That's what turns a certificate from decoration into proof.
