Quick reference

Glossary

Every term from the course in one place, explained in a line or two. Next to each term — the lesson that covers it in depth.

Agent
Software that takes a goal, plans, uses tools, checks its own result — and repeats until it succeeds. Lesson 1
Terminal / command line (CLI)
A text interface for working with your computer: type a command, get an answer. Claude Code's home. Terminal guide
Context window
A conversation's "working memory": everything said, read and run. It's limited — so you manage it deliberately. Lesson 4
Token
The unit of text a language model processes (roughly three-quarters of a word). Context and cost are measured in tokens. Lesson 4
CLAUDE.md
The project's memory file — loaded automatically at the start of every conversation. Whatever is in it, Claude simply knows. Lesson 4
Plan Mode
A mode where Claude only reads and explores — changing anything is forbidden — and presents a plan for your approval. Lesson 2
Custom slash command
A Markdown file in .claude/commands/ that turns a whole prompt into a one-word command. Lesson 5
Skill
A knowledge package Claude loads by itself when the task fits — based on its description. You don't have to remember to ask. Lesson 5
Hook
Your command running automatically around Claude's actions — enforcing quality, blocking danger, sending alerts. A mechanism, not a request. Lesson 6
MCP (Model Context Protocol)
An open protocol connecting external tools to Claude: a browser, databases, Slack and more. The agents' "USB socket". Lesson 7
Subagent
A specialist agent with its own instructions, tools and context, activated by the main agent when a task fits it. Lesson 8
Prompt injection
An attempt to plant instructions for the agent inside content it reads — a foreign README, a web page, a comment. The defense: boundaries in code, not trust. Lesson 9
Least privilege
Giving every agent and tool exactly the permissions the task requires — not one more. readonly when possible. Lesson 7
Headless mode
Running Claude as a one-shot command with no interface (claude -p) — the basis for scripts and automation. Lesson 10
CI (Continuous Integration)
An automated process running on every code change in the repo — tests, builds, and in our case Claude agents too. Lesson 10
Agent SDK
A TypeScript/Python library giving you Claude Code's engine in code — for building your own agents and squads. Lesson 11
Feedback loop
A tool that lets the agent check itself: tests, a browser, compilation. Without it — autonomy is guessing. Lesson 11
Agent squad
A group of agents with defined roles, an orchestrator, shared memory and deliverable contracts — working together on one goal. Lesson 12
Orchestrator
Whoever breaks a goal into tasks, delegates to specialists and merges deliverables — the main conversation or an SDK script. Lesson 12
Deliverable contract
A precise definition of what each agent in a squad receives and returns. The point where squads fail — or succeed. Lesson 12
Git worktree
An additional working copy of the same repo in a separate folder — letting several agents work in parallel without stepping on each other. Lesson 12
Commit
A "save point" in git. Small, frequent commits are the safety net of working with agents. Lesson 3
Branch
A parallel line of work in git you can merge back or discard — the safe place to let an agent work. Lesson 3
Pull Request (PR)
A request to merge a branch, with room for review and discussion. The main human checkpoint over agent work. Lesson 3
GitHub
A site hosting git repositories in the cloud: backup, sharing, and Pull Requests. Git is the software on your machine — GitHub is the cloud above it. Setup guide
GitHub CLI (gh)
GitHub's official command-line tool. After a one-time gh auth login, Claude can open PRs and manage issues for you. Setup guide
