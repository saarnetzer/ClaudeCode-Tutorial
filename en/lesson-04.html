Memory and context: CLAUDE.md and context management

The difference between "Claude that works okay" and "Claude that feels like a veteran teammate" is almost always one small file: CLAUDE.md. In this lesson we'll teach Claude our project once — and keep conversations sharp and focused.

What you'll learn

  • What the context window is and why it's your scarcest resource
  • The CLAUDE.md file: what goes in and what doesn't
  • Three memory levels: project, personal, and global
  • Techniques for managing long conversations

First, a concept: the context window

Every conversation with Claude has limited "working memory" — the context window. Everything said, every file read and every command output takes up room in it. When it fills up, older details get compressed or forgotten. Two practical rules follow:

  • A new conversation for every new task. Finished a feature? /clear. There's no reason to drag thousands of lines of stale, distracting context into a new task.
  • Whatever always matters — belongs in a file, not the conversation. That is exactly CLAUDE.md's job.

CLAUDE.md — the project's ID card

At the start of every conversation, Claude automatically reads the CLAUDE.md file in the project folder. Whatever is written there — it simply knows, without you repeating it. To generate a first draft automatically:

/init

Claude scans the project and writes a starter file. But the real value comes from your editing. A recommended structure:

CLAUDE.md# MyShop — online store

## Commands
- Local dev: `npm run dev`
- Tests: `npm test` (required before every commit)
- Lint: `npm run lint`

## Architecture
- Frontend: React + Vite in `client/`
- Backend: Express in `server/`, routes in `server/routes/`
- DB: PostgreSQL via Prisma. Schema in `prisma/schema.prisma`

## Important rules
- All user-facing text in Hebrew. Variable names in English
- Never touch `legacy/` without explicit approval
- Dates always UTC on the server, convert to local time only for display
- After any schema change run `npx prisma generate`
✅ The CLAUDE.md quality test Ask yourself: "if a new developer joined tomorrow, what would I have to tell them on day one?" — that's exactly what belongs in the file. Short, factual, no rambling. A huge file hurts more than it helps, because it loads into every conversation.

Updating as you work

Caught yourself explaining something to Claude for the second time? That's a sign it belongs in memory. Start a message with a hash # — and Claude will offer to add it to the memory file:

# always use axios, not fetch, in this project

Three memory levels

FileScopeWhen
./CLAUDE.mdThe project — shared with the team (in git)Commands, architecture, team rules
./CLAUDE.local.mdThe project — you only (outside git)Local paths, personal per-project preferences
~/.claude/CLAUDE.mdEvery project on your machine"answer in Hebrew", personal code style
💡 Where's that on Windows? The ~ symbol means your home folder. On Windows that's C:\Users\<username> — so ~/.claude/CLAUDE.md is C:\Users\<username>\.claude\CLAUDE.md.

In a large project you can also put CLAUDE.md files in subfolders — Claude loads them when working in the relevant area.

Managing long conversations

  • /compact — compresses history into a summary. Use at a natural stopping point (after a commit, before a new subtask).
  • /clear — full reset. Better than compact when switching to an unrelated task.
  • Deliberate interim summaries: before a long break ask "summarize into PROGRESS.md what we did, what works and what's left" — and open the next conversation with "read PROGRESS.md and let's continue".
💡 The organizing principle Context is a precious resource: every wasted token reduces focus. Agents work best when the context holds exactly what's relevant — no less, and no more. Think of yourselves as the agent's context managers.

Exercises

Exercise 4.1 A first CLAUDE.md

In a project you worked on in previous lessons, run /init. Read the generated file, delete anything unnecessary, and add two personal rules of your own (e.g. "user-facing text in Hebrew"). Open a new conversation and check the rules really apply.

How to verify it works

After /clear, ask for something the rule should affect — e.g. "add a new button" — and check the text comes out in the right language without asking. If so: memory works.

Exercise 4.2 Global memory

Create ~/.claude/CLAUDE.md with 2–3 preferences that are always true for you (language, answer style, favorite tools). Open Claude in two different folders and verify the preferences apply in both.

Sample content 
# Personal preferences
- answer me in Hebrew, code in English
- before a big change - show a short plan
- prefer a simple solution over a "clever" one
Exercise 4.3 Passing the baton between conversations

Start a multi-step task (e.g.: an "About" page + navigation + styling). Midway, ask Claude to write a progress summary to PROGRESS.md. Run /clear, then: "read PROGRESS.md and continue where we stopped". Verify it truly picks up correctly.

Why this matters

This technique — keeping state in files instead of conversation memory — is a cornerstone of autonomous agents (Lesson 11). An agent that runs for hours needs "external memory" that survives context resets. You're already practicing it by hand.

Self-check

1. What happens with CLAUDE.md at the start of every conversation?

2. You finished a feature and are moving to something unrelated. What's right?

3. How do you add a rule to memory mid-conversation?

Lesson summary

  • The context window is limited — manage it deliberately: /clear between tasks, /compact at stopping points
  • CLAUDE.md = what you'd tell a new developer on day one
  • Three levels: project (shared), local (personal per project), global (~/.claude)
  • Important knowledge lives in files — not conversation memory
