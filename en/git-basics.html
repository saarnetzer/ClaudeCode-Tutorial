Git and GitHub from scratch — install, account, connection

Lesson 3 assumes you have Git installed and a GitHub account. Don't? This page sorts that out in fifteen minutes, step by step — and from that install onward you won't need to memorize git commands: Claude runs them for you.

First: what are they, and what's the difference?

  • Git is software running on your computer that saves "save points" (commits) of your project. Like saving in a game: you can always go back. It works offline and needs no account.
  • GitHub is a website (owned by Microsoft) that stores a copy of your project in the cloud: backup, sharing with others, and Pull Requests. For that you do need an account.

In other words: Git = the save engine on your machine, GitHub = the cloud above it. The course needs both — Git from Lesson 3, and GitHub for some exercises and for Lesson 10.

💡 Why does this matter especially in an agent course? When an AI agent edits dozens of files for you, Git is the safety net: every change is recorded, and every mistake is reversible in 10 seconds. That's why Lesson 3 comes so early in the course.

Step 1: install Git

It may already be installed — check in the terminal first:

git --version

Got a version number? Skip to step 2. Got "command not found"? Install:

🪟 Windows

PowerShellwinget install --id Git.Git -e

Or download the installer from the official site: git-scm.com/download/win (click "Next" through all the defaults — they're good). When it finishes, close and reopen the terminal.

🍎 macOS

xcode-select --install

This installs Apple's developer tools, which include Git. Alternative for Homebrew users: brew install git.

🐧 Linux

sudo apt install git      # Ubuntu / Debian
sudo dnf install git      # Fedora
✅ Check Open a new terminal and run git --version. A version number = installed. Onward.

Step 2: introduce yourself to Git

Git signs every save point with a name and email. Set them once (same commands on every OS):

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Use the same email you'll open your GitHub account with in the next step — that way your contributions are attributed correctly.

Step 3: open a GitHub account (free)

  1. Go to github.com/signup.
  2. Enter an email (the one from the previous step), choose a strong password, and pick a username.
  3. Confirm the verification code sent to your email — and that's it, you have an account.
⚠️ A moment before you choose a username Your username appears in the URL of every project you publish (e.g. github.com/your-name) — and it's also your public developer résumé. Pick something professional you'll be happy to see five years from now; short, no random numbers.

Strongly recommended: enable two-factor authentication (2FA) — in account settings: Settings → Password and authentication → Two-factor authentication. Five minutes that protect all your code.

Step 4: connect your machine to the account

The most convenient way — and the one this course uses — is the GitHub CLI (the gh command):

Install

Windows (PowerShell)winget install --id GitHub.cli -e
macOSbrew install gh
Linuxsudo apt install gh   # or follow the instructions at cli.github.com

Sign in (once)

gh auth login

Answer the questions like this: GitHub.com → HTTPS → Login with a web browser. An 8-character code appears — copy it, confirm in the browser that opens, and you're done.

✅ Final check that everything is connected Run gh auth status. If you see a ✓ next to your username — your machine is connected to the account, and you're fully ready for Lesson 3, including the Pull Request exercise.

That's it — you're set

Notice what we did not do here: we learned no git commands beyond config. That's deliberate — in Lesson 3 you'll discover that all the day-to-day work (commits, branches, recovery, PRs) is asked of Claude in plain words, and it runs the right commands. The infrastructure you just built is all that was missing.
