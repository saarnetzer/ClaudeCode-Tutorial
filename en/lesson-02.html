Everyday fundamentals

This lesson turns you from a hesitant user into a fluent one: how to phrase requests that get excellent results, how to control what Claude is allowed to do, and which commands and keys save serious time.

What you'll learn

  • The single most important principle of phrasing requests
  • The three permission modes, including Plan Mode
  • The built-in slash commands you must know
  • How Claude explores an existing project

How to phrase a good request

The most important rule: give context and a goal, not just an order. Claude fills gaps well, but the more precise the request — the closer the result is to what you wanted, in one round.

Weak request 😕Strong request 💪
"fix the bug" "When you click 'Send' on the signup form without an email, the page crashes. Find the cause and fix it, and add validation with a friendly error message."
"add tests" "Add tests for utils/dates.js, including leap-year and timezone edge cases. Use the framework already in the project."
"improve the code" "The processOrders function is slow with 10,000 orders. Measure, find the bottleneck, and propose a fix — before changing anything."

Notice the pattern in the last example: "propose before you change". That approach is so useful it has an entire built-in mode — Plan Mode, coming right up.

✅ Pointing at files Typing @ followed by a file path (e.g. @src/app.js) attaches the file to the request's context. It's the fast way to say "look exactly here".

Permission modes: who decides what's allowed

Claude Code is safe by default: it asks for approval before editing files and running commands. Shift+Tab switches between modes:

ModeWhat happensWhen to use
Normal (default)Manual approval for every edit and commandNew projects, sensitive operations
Auto-accept editsFile edits auto-approved; commands still askRoutine work in a familiar project
Plan ModeClaude only reads and explores — changing anything is forbidden. At the end it presents a plan for your approvalBig/risky tasks, learning a project

Plan Mode is the professionals' secret weapon. For a complex task, the right process is: enter Plan Mode, let Claude explore and present a plan, refine the plan in dialogue — and only then approve execution. Fixing a sentence in a plan is a hundred times cheaper than fixing a thousand lines of code written in the wrong direction.

You can also approve permissions permanently: the /permissions command shows and manages a rule list — for example always allowing npm test but never rm -rf. Allow/deny rules, protecting secrets and all the other defense layers get an entire lesson — Lesson 9.


  

    🛑 About the scary flag
    There's a flag called --dangerously-skip-permissions that disables all approval questions. Do not use it on your personal machine. We'll discuss it in Lesson 10 — in isolated environments (sandbox/container) it has a place, and only there.

Working on an existing project

  
The real magic shows on an existing project. Open Claude in a project folder you know and ask questions before changing anything:

  
what does this project do? give me an overview of the structure, the technologies, and the entry point

  
where is user login handled? explain the flow step by step with file names

  
Claude will use search and read tools to answer — and it's completely safe, because reading changes nothing. Need to get to know a new project at work? This is one of the fastest ways that exist today.


  
Exercises

  

    
Exercise 2.1 Same task, two phrasings

    
In a new folder ask: "build a calculator". Take the result. Then run /clear and ask: "build a calculator in a single HTML page: four operations, modern dark styling, keyboard support, and divide-by-zero handled with a friendly message". Compare the two results.

    
What should happen
      
Both will work, but the second will be far closer to what you imagined — without fix-up rounds. The takeaway: spelling out requirements up front is the best-paying investment in working with agents.

    

  


  

    
Exercise 2.2 Plan Mode in action

    
Open any existing project (or deliberately break the calculator from the previous exercise). Switch to Plan Mode with Shift+Tab (twice), and ask: "I want to add a saved calculation history. Explore the code and present a plan". Read the plan, request one change to it ("keep only the last 10"), and only then approve execution.

    
What should happen
      
In Plan Mode you'll see Claude only reading — no edit-approval prompts. The plan appears at the end, and your requested change goes into it before a single line of code is written. This is exactly the workflow for serious tasks.

    

  


  

    
Exercise 2.3 Exploring a stranger's project

    
Download some open-source project (git clone of a library that intrigues you), open Claude in it, and ask three questions: what's the structure, how would you add feature X, and where are the tests. Try to reach an understanding of the project in 10 minutes.

    
Tip
      
An especially good question for unfamiliar projects: "if I had to fix a bug in [area], which 3 files would I start reading?" — the answer maps the territory that really matters.
