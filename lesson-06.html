Hooks — אוטומציה של תהליך העבודה

עד עכשיו ביקשנו מ‑Claude לעשות דברים. Hooks הם ההפך: קוד שלכם שרץ אוטומטית סביב הפעולות של Claude — בלי לבקש, בלי לסמוך על זיכרון, במאה אחוז מהמקרים. זה ההבדל בין "בבקשה תריץ פורמט" לבין "פורמט רץ תמיד, נקודה".

מה נלמד בפרק

  • מה זה Hook ובאילו אירועים אפשר להתחבר
  • Hook ראשון: פורמט אוטומטי אחרי כל עריכה
  • Hooks כשומרי סף: חסימת פעולות מסוכנות
  • למה Hooks קריטיים לסוכנים אוטונומיים

הרעיון

Hook הוא פקודת מערכת שמוגדרת בקובץ ההגדרות של Claude Code ורצה אוטומטית כשקורה אירוע מסוים. האירועים העיקריים:

אירועמתי רץשימוש טיפוסי
PreToolUseלפני שכלי מופעל (עריכה, פקודה...)חסימת פעולות אסורות
PostToolUseאחרי שכלי הופעל בהצלחהפורמט, lint, בדיקות אוטומטיות
UserPromptSubmitכששולחים הודעההזרקת הקשר, ולידציה של בקשות
Stopכש‑Claude מסיים לענותהתראה, בדיקת "באמת סיימת?"
Notificationכש‑Claude ממתין לאישורצליל/הודעה כשצריך אתכם

ההגדרות יושבות ב‑.claude/settings.json (לפרויקט, משותף בצוות) או ~/.claude/settings.json (אישי). הדרך הנוחה להתחיל: הפקודה /hooks בתוך Claude Code, שמדריכה אתכם אינטראקטיבית.

דוגמה 1: פורמט אוטומטי אחרי כל עריכה

.claude/settings.json{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\" 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}

מה קורה כאן: בכל פעם ש‑Claude עורך או כותב קובץ (matcher תופס את הכלים Edit ו‑Write), רץ prettier על הקובץ שנגעו בו. מעכשיו אין "שכחתי לפרמט" — יש חוק טבע.

💡 למה לא פשוט לכתוב את זה ב‑CLAUDE.md? כי הוראה בזיכרון היא בקשה — המודל כמעט תמיד יכבד אותה, אבל "כמעט תמיד" זה לא "תמיד". Hook הוא מנגנון — הוא רץ בכל מקרה. כלל אצבע: העדפות → CLAUDE.md; חוקים שאסור להפר → Hooks.

דוגמה 2: שומר סף שחוסם פעולות מסוכנות

‏Hook של PreToolUse מקבל ב‑stdin את פרטי הפעולה המתוכננת (JSON), ויכול לחסום אותה: יציאה עם קוד 2 אומרת ל‑Claude "אסור, והנה הסיבה" (מה שנכתב ל‑stderr חוזר אליו כהסבר).

.claude/hooks/guard.py#!/usr/bin/env python3
import json, sys, re

data = json.load(sys.stdin)
if data.get("tool_name") == "Bash":
    cmd = data.get("tool_input", {}).get("command", "")
    banned = [r"rm\s+-rf\s+[/~]", r"git\s+push\s+--force", r"DROP\s+TABLE"]
    for pattern in banned:
        if re.search(pattern, cmd, re.IGNORECASE):
            print(f"Blocked dangerous command: {cmd}", file=sys.stderr)
            sys.exit(2)   # exit 2 = block + explain to Claude
sys.exit(0)
.claude/settings.json (קטע){
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "python3 .claude/hooks/guard.py" }
        ]
      }
    ]
  }
}

עכשיו גם אם Claude ינסה (או ישתכנע על ידי בקשה מבולבלת שלכם...) להריץ rm -rf / — הפעולה תיחסם ברמת המערכת, והוא יקבל הסבר ויחפש דרך אחרת.

דוגמה 3: התראה כשצריך אתכם

נתתם ל‑Claude משימה ארוכה והלכתם להכין קפה? שיודיע כשהוא צריך אישור:

.claude/settings.json (קטע, macOS){
  "hooks": {
    "Notification": [
      {
        "hooks": [
          { "type": "command", "command": "afplay /System/Library/Sounds/Glass.aiff" }
        ]
      }
    ]
  }
}

בלינוקס אפשר notify-send "Claude מחכה לך", ובווינדוס סקריפט PowerShell קצר.

למה זה שער לאוטונומיה

חשבו רגע מה בנינו: מערכת שבה לסוכן יש חופש פעולה, אבל גבולות שנאכפים בקוד, לא בהבטחות. פורמט ואיכות נאכפים אוטומטית (PostToolUse), פעולות הרסניות חסומות פיזית (PreToolUse), ובני האדם מקבלים התראה בנקודות ההכרעה (Notification). זו בדיוק התשתית שתאפשר לנו בפרקים 9–10 להרפות מההגה בביטחון: ככל שהגבולות קשיחים יותר — אפשר לתת לסוכן יותר חופש בתוכם.

תרגילים

תרגיל 6.1 Hook ראשון

הגדירו PostToolUse שרץ אחרי כל עריכת קובץ ומוסיף שורת לוג לקובץ .claude/edits.log (תאריך + נתיב). בקשו מ‑Claude לערוך משהו, ובדקו שהלוג מתעדכן. טיפ: אפשר לבקש מ‑Claude עצמו לכתוב את ההגדרה!

פתרון לדוגמה 
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"$(date '+%F %T') $CLAUDE_FILE_PATHS\" >> .claude/edits.log"
          }
        ]
      }
    ]
  }
}

לוג כזה הוא דרך מצוינת "לראות" מה סוכן עשה בריצות ארוכות.

תרגיל 6.2 שומר סף משלכם

כתבו PreToolUse (אפשר להתבסס על ה‑Python מלמעלה) שחוסם כל עריכה של קבצים בתיקייה secrets/. צרו תיקייה כזו עם קובץ דמה, ובקשו מ‑Claude במפורש לערוך אותו — וודאו שהוא נחסם ומסביר לכם למה.

כיוון לפתרון

ב‑matcher תפסו Edit|Write. בסקריפט בדקו אם tool_input.file_path מכיל secrets/ — ואם כן, exit 2 עם הסבר ב‑stderr. החוויה החשובה: לראות ש‑Claude מקבל את החסימה, מסביר לכם אותה, ולא מנסה לעקוף.

תרגיל 6.3 "באמת סיימת?"

הגדירו Stop hook שמריץ את הטסטים של הפרויקט כש‑Claude מסיים לענות, וכותב את התוצאה לקובץ. שדרוג: חשבו (ובדקו בתיעוד של /hooks) איך Stop hook יכול להחזיר את Claude לעבודה אם הטסטים נכשלו.

כיוון לפתרון

‏Stop hook שמסיים עם קוד 2 ומסביר ב‑stderr ("הטסטים נכשלו, תקן לפני שאתה מסיים") מחזיר את Claude לעבודה. היזהרו מלולאה אינסופית — הגבילו את הבדיקה כך שלא תיכשל לנצח. הדפוס הזה, "לא סיימת עד שהבדיקות ירוקות", הוא אחד ממנועי האוטונומיה החזקים ביותר.

סיכום הפרק

  • Hooks = קוד שלכם שרץ אוטומטית סביב פעולות של Claude
  • PostToolUse לאכיפת איכות, PreToolUse לחסימת סכנות, Notification להתראות
  • exit code 2 + stderr = חסימה עם הסבר שחוזר ל‑Claude
  • העדפות → CLAUDE.md; חוקים מוחלטים → Hooks
