MCP — מחברים את Claude לעולם

מהקופסה, Claude Code יודע לעבוד עם קבצים וטרמינל. אבל מה עם דפדפן אמיתי? מסד נתונים? ה‑Slack של הצוות? פרוטוקול MCP הוא "שקע ה‑USB" שמחבר ל‑Claude כלים חדשים — ובפרק הזה נחבר כמה כאלה.

מה נלמד בפרק

  • מה זה MCP ולמה הוא נהיה סטנדרט עולמי
  • חיבור שרת MCP ראשון: שליטה בדפדפן
  • חיבור למסד נתונים ולשירותים חיצוניים
  • רמות תצורה (scopes) ושיקולי אבטחה

הרעיון

MCP‏ (Model Context Protocol) הוא פרוטוקול פתוח שמגדיר איך מודל AI מדבר עם כלים חיצוניים. שרת MCP הוא תוכנית קטנה שחושפת "כלים" (למשל: open_page,‏ run_query,‏ send_message), ו‑Claude — כשהוא מחובר לשרת — רואה את הכלים האלה ויכול להפעיל אותם בדיוק כמו שהוא מפעיל עריכת קבצים. יש היום אלפי שרתי MCP מוכנים: GitHub, Slack, Postgres, Playwright, Figma, Notion, Stripe ועוד.

💡 החיבור לתמונה הגדולה זוכרים את ההגדרה של סוכן — "מודל שמפעיל כלים בלולאה"? MCP פשוט מרחיב את ארגז הכלים. יותר כלים = הסוכן יכול לפעול על עוד חלקים של העולם. סוכן עם דפדפן יכול לבדוק בעצמו את האתר שהוא בנה. זה שינוי מהותי.

שרת ראשון: דפדפן עם Playwright

נחבר שרת שנותן ל‑Claude דפדפן אמיתי:

claude mcp add playwright -- npx @playwright/mcp@latest

זהו. פתחו את Claude ונסו:

פתח את הדפדפן על http://localhost:3000, מלא את טופס ההרשמה
עם נתונים לדוגמה, שלח, וצלם מסך של התוצאה. אם משהו שבור - תקן את הקוד ובדוק שוב

קראו שוב את סוף המשפט: "אם משהו שבור — תקן ובדוק שוב". עכשיו ל‑Claude יש לולאת משוב מלאה על UI: הוא כותב קוד, רואה בעצמו את התוצאה בדפדפן, ומתקן. בדיוק כמו מפתח אנושי.

פקודות ניהול שימושיות:

claude mcp list          # אילו שרתים מחוברים ומה מצבם
claude mcp get playwright # פרטי שרת
claude mcp remove playwright

שרת שני: מסד נתונים

claude mcp add db -- npx -y @modelcontextprotocol/server-postgres "postgresql://readonly_user:pass@localhost:5432/shop"

ואז בשיחה:

כמה הזמנות נפתחו החודש לעומת חודש שעבר, בפילוח לפי עיר?
תציג טבלה ותסביר מה בולט

‏Claude יכתוב את ה‑SQL, יריץ דרך השרת, ויפרש את התוצאות בעברית.

🛑 כלל הזהב: הרשאות מינימום שימו לב שבדוגמה חיברנו משתמש readonly_user. לעולם אל תחברו סוכן למסד נתונים אמיתי עם הרשאות כתיבה "כי נוח". אותו עיקרון לכל שרת MCP: התקינו רק שרתים ממקור אמין, ותנו להם את ההרשאה המינימלית שמספיקה למשימה. כלי שהסוכן לא צריך — אל תחברו.

רמות תצורה (Scopes)

Scopeאיפה נשמרלמי
local (ברירת מחדל)הגדרות אישיות של הפרויקטרק אתם, רק בפרויקט הזה
projectקובץ .mcp.json בשורש הריפוכל הצוות (נכנס ל‑git)
userהגדרות המשתמש שלכםאתם, בכל הפרויקטים
# שרת שכל הצוות יקבל אוטומטית:
claude mcp add --scope project github -- npx -y @modelcontextprotocol/server-github

קובץ .mcp.json בריפו הוא עוד לבנה בתשתית הצוותית: מי שמשכפל את הפרויקט מקבל לא רק קוד, אלא גם את כל הכלים שהסוכן צריך כדי לעבוד עליו.

תרגילים

תרגיל 7.1 לולאת משוב ויזואלית

חברו את שרת Playwright. פתחו את אחד הפרויקטים מהקורס ובקשו: "פתח את הדף בדפדפן, צלם מסך, ותקן שלוש בעיות עיצוב שאתה מזהה — אחרי כל תיקון צלם שוב וודא שהשתפר". צפו בלולאה עובדת.

מה אמור לקרות

‏Claude יפתח את הדף, יצלם, יזהה בעיות (יישור, צבעים, גלישת טקסט), יתקן בקוד ויצלם שוב להשוואה. אם הדף לא נטען — ודאו שהרצתם שרת מקומי או בקשו ממנו לפתוח את הקובץ ישירות (file://).

תרגיל 7.2 בדיקת קצה־לקצה אוטומטית

המשך לתרגיל הקודם: בקשו מ‑Claude לכתוב תרחיש בדיקה מלא לאפליקציה שלכם (למשל למחשבון: "לחץ 7, +, 3, = וודא שמוצג 10") ולהריץ אותו דרך הדפדפן. אחר כך שברו משהו בכוונה בקוד ובקשו להריץ שוב — וודאו שהבדיקה תופסת את השבירה.

למה זה חשוב

בדיקות שהסוכן יכול להריץ בעצמו הן תנאי הכרחי לאוטונומיה: בלעדיהן אין לו דרך לדעת אם הצליח. "שברו ובדקו שנתפס" מוודא שהבדיקה אמיתית ולא תמיד־ירוקה.

תרגיל 7.3 שרת לבחירתכם

בחרו שרת MCP אחד שרלוונטי לחיים שלכם (GitHub? Notion? מסד נתונים של פרויקט צד?), חברו אותו ב‑scope המתאים, ובצעו איתו משימה אמיתית אחת. שאלו קודם את Claude: "אילו כלים אתה מקבל מהשרת הזה?"

טיפ

השאלה "אילו כלים יש לך עכשיו?" היא דרך מצוינת להבין כל שרת חדש. ואם משהו לא עובד — claude mcp list מראה אם השרת בכלל הצליח להתחבר.

סיכום הפרק

  • MCP = פרוטוקול סטנדרטי שמוסיף ל‑Claude כלים: דפדפן, DB, שירותי ענן
  • חיבור בפקודה אחת: claude mcp add שם -- פקודה
  • ‏scope‏ project + קובץ .mcp.json = כלים משותפים לכל הצוות
  • הרשאות מינימום תמיד: readonly כשאפשר, ורק שרתים ממקור אמין
