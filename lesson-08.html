Subagents — צוות של סוכני משנה

למה סוכן אחד כשאפשר צוות? Subagents הם סוכנים מתמחים — בודק קוד, כותב טסטים, חוקר — שהסוכן הראשי מפעיל בעצמו כשמשימה מתאימה להם. כל אחד עם ההנחיות שלו, הכלים שלו, וחלון הקשר נקי משלו.

מה נלמד בפרק

  • מה זה Subagent ולמה הקשר נפרד הוא יתרון ענק
  • יצירת Subagent ראשון: סוקר קוד
  • הגבלת כלים לכל סוכן — הרשאות לפי תפקיד
  • מתי subagents עוזרים ומתי הם מיותרים

הרעיון

‏Subagent הוא "עובד" שהסוכן הראשי יכול להאציל לו משימה. שלוש תכונות הופכות אותו לחזק:

  • הקשר נפרד. ה‑subagent עובד בחלון הקשר נקי משלו. הוא יכול לקרוא חמישים קבצים ולהחזיר לסוכן הראשי רק את השורה התחתונה — וחלון ההקשר של השיחה הראשית נשאר נקי. זה פותר את בעיית "השיחה מתנפחת" מפרק 4.
  • התמחות. לכל subagent יש system prompt משלו: הנחיות מפורטות לתפקיד אחד, בלי רעש.
  • הרשאות משלו. אפשר לקבוע אילו כלים מותרים לו — סוקר קוד, למשל, מקבל קריאה בלבד.

‏Subagent מוגדר כקובץ Markdown ב‑.claude/agents/ (לפרויקט) או ~/.claude/agents/ (אישי). אפשר גם לנהל אותם עם הפקודה האינטראקטיבית /agents.

Subagent ראשון: סוקר קוד

.claude/agents/code-reviewer.md---
name: code-reviewer
description: סוקר קוד קפדני. יש להפעיל אותו יזום (proactively) אחרי
  כל שינוי קוד משמעותי, ולפני כל קומיט.
tools: Read, Grep, Glob, Bash
---

אתה סוקר קוד בכיר. כשאתה מקבל משימה:
1. הרץ git diff כדי לראות מה השתנה
2. עבור על כל קובץ ששונה ובדוק:
   - באגים לוגיים ומקרי קצה שלא טופלו
   - בעיות אבטחה (קלט לא מסונן, סודות בקוד, הרשאות)
   - קוד כפול או מורכבות מיותרת
   - עמידה בסגנון הקיים של הפרויקט
3. דרג כל ממצא: קריטי / כדאי לתקן / קוסמטי

החזר דוח מסודר עם ציון קובץ ושורה לכל ממצא.
אל תערוך קבצים - אתה סוקר, לא מתקן.

שימו לב לשלושה דברים:

  • ה‑description אומר במפורש מתי להפעיל — כולל המילה "proactively", שמעודדת את הסוכן הראשי להפעיל אותו בלי שתבקשו.
  • שורת tools נותנת לו קריאה וחיפוש בלבד (ו‑Bash בשביל git diff) — אין לו Edit או Write. ההנחיה "אל תערוך" מגובה בהרשאות. זה עקרון ה‑Hooks מפרק 6 שוב: לא הבטחות, מנגנונים.
  • גוף הקובץ הוא ה‑system prompt המלא שלו — תהליך עבודה מפורט, צעד־צעד.

אחרי שמירת הקובץ, אפשר להפעיל מפורשות ("תבקש מ‑code-reviewer לעבור על השינויים") — או פשוט לעבוד רגיל ולראות שהסוכן הראשי קורא לו לבד אחרי שינויים גדולים.

עוד שני עובדים לצוות

.claude/agents/test-writer.md---
name: test-writer
description: כותב טסטים. הפעל כשצריך להוסיף בדיקות לקוד חדש או קיים.
---

אתה מומחה לכתיבת טסטים. זהה את ה-framework הקיים בפרויקט
והשתמש בו. לכל פונקציה כתוב בדיקות למקרה התקין, למקרי קצה ולמקרי כישלון.
הרץ את הטסטים וודא שהם עוברים לפני שאתה מסיים.
טסט שנכשל על קוד קיים = ממצא חשוב, דווח עליו ואל תסתיר.
.claude/agents/researcher.md---
name: researcher
description: חוקר קוד לקריאה בלבד. הפעל לשאלות "איך עובד X" או
  "איפה נמצא Y" בפרויקטים גדולים, כדי לחסוך הקשר בשיחה הראשית.
tools: Read, Grep, Glob
---

אתה חוקר קוד. ענה על השאלה שקיבלת בצורה תמציתית:
מנגנון, קבצים מרכזיים (עם נתיבים), וזרימת הנתונים.
החזר תשובה קצרה וממוקדת - לא את כל מה שקראת.

ה‑researcher מדגים את דפוס ה"הקשר הנקי" במיטבו: הוא קורא המון ומחזיר מעט. בפרויקטים גדולים זה חוסך אלפי טוקנים בשיחה הראשית.

⚠️ מתי לא להשתמש ‏Subagent מתחיל כל משימה "קר" — בלי היסטוריית השיחה — ותקשורת איתו עולה זמן וטוקנים. למשימות קטנות בשיחה רציפה הוא סרבול מיותר. הכלל: משימה עצמאית, גדולה או כזו שדורשת התמחות — subagent; דיאלוג שוטף — הסוכן הראשי.

תרגילים

תרגיל 8.1 מקימים את הצוות

צרו את code-reviewer בפרויקט שלכם (העתיקו מהדוגמה והתאימו לכללים שלכם). עשו שינוי קוד עם באג קטן בכוונה (למשל תנאי הפוך), ובקשו סקירה. בדקו שהבאג נתפס ושמקבלים דוח מדורג.

מה אמור לקרות

תראו בממשק שהמשימה נמסרת ל‑subagent (סימון נפרד), והדוח יחזור מובנה לפי ההנחיות. אם הסוקר "מפספס" את הבאג — חדדו את ה‑system prompt שלו. כתיבת הנחיות לסוכן היא מיומנות שמתאמנים עליה.

תרגיל 8.2 שרשרת עבודה

צרו גם את test-writer, ואז תנו לסוכן הראשי משימה משולבת: "הוסף פונקציית חישוב הנחה לפי כמות, תן ל‑test-writer לכסות אותה בטסטים, ואז תן ל‑code-reviewer לסקור את הכול". צפו בניהול הצוות.

מה לחפש

הסוכן הראשי מתפקד כמנהל: כותב את הקוד, מאציל את הטסטים, מאציל את הסקירה, ומאחד את התוצאות. אם הסקירה מעלה ממצא קריטי — בקשו ממנו לתקן ולהריץ סקירה חוזרת. קיבלתם pipeline איכות שלם בפקודה אחת.

תרגיל 8.3 סוכן משלכם

חשבו על התמחות שחסרה לכם — מתעד API? בודק נגישות? מתרגם UI? — וכתבו לה subagent מלא: description שגורם לו להיקרא בזמן הנכון, כלים לפי הצורך האמיתי, ותהליך עבודה מפורט. הפעילו אותו על משימה אמיתית.

רעיון לדוגמה

‏a11y-checker: כלים Read/Grep/Glob בלבד; בודק alt לתמונות, ניגודיות צבעים, תוויות לטפסים, ניווט מקלדת; מחזיר דוח עם חומרה ותיקון מוצע לכל ממצא. עובד מצוין בשילוב עם Playwright מפרק 7.

סיכום הפרק

  • ‏Subagent = סוכן מתמחה עם הנחיות, כלים והקשר נפרדים משלו
  • מוגדר כ‑Markdown ב‑.claude/agents/; ה‑description קובע מתי ייקרא
  • הרשאות לפי תפקיד: סוקר לא כותב, חוקר לא עורך
  • הקשר נפרד = קורא הרבה, מחזיר מעט — השיחה הראשית נשארת נקייה
