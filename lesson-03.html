עבודה עם Git ו‑GitHub

Git הוא רשת הביטחון שהופכת עבודה עם סוכן ממפחידה לרגועה: כל שינוי נרשם, וכל טעות הפיכה. החדשות הטובות — עם Claude Code לא צריך לשנן אף פקודת git. מבקשים במילים, הוא מבצע.

מה נלמד בפרק

  • למה Git חיוני במיוחד בעבודה עם סוכני AI
  • קומיטים וענפים בשפה חופשית
  • יצירת Pull Request מהטרמינל
  • שחזור מטעויות — הקלף החזק שלכם

למה Git + סוכן = שילוב מנצח

כשסוכן עורך עשרות קבצים בשבילכם, שתי שאלות הופכות קריטיות: "מה בדיוק הוא שינה?" ו־"איך מבטלים אם זה רע?". Git עונה על שתיהן. לכן הכלל: לפני כל משימה משמעותית — קומיט. אחרי כל שלב שהצליח — קומיט. קומיטים קטנים ותכופים הם חגורת הבטיחות של עבודה עם AI.

💡 חדשים ב‑Git? זה בסדר גמור. תחשבו על Git כ"נקודות שמירה במשחק": קומיט = שמירה. אפשר תמיד לחזור לשמירה קודמת. ענף (branch) = התחלה של קו עלילה חלופי שאפשר למזג חזרה או לזרוק. עם Claude Code אתם לא צריכים לדעת יותר מזה כדי להתחיל.

הכול בשפה חופשית

במקום לזכור תחביר, פשוט מבקשים:

מה השתנה בפרויקט מאז הקומיט האחרון? תראה לי סיכום לפני שנשמור
תעשה קומיט לשינויים עם הודעה מתאימה
תפתח ענף חדש בשם feature/dark-mode ותעבור אליו
מי שינה את הפונקציה הזאת לאחרונה ולמה? תבדוק בהיסטוריה

Claude מריץ את פקודות ה‑git הנכונות (תראו אותן ותאשרו), מנסח הודעות קומיט איכותיות לפי תוכן השינוי, ואפילו יודע לחקור היסטוריה כדי לענות על שאלות "בלשיות".

תרחיש אמיתי: פיצ'ר מלא בענף

1. תפתח ענף feature/contact-form
2. תוסיף טופס יצירת קשר לעמוד הראשי עם ולידציה
3. תריץ את הטסטים
4. אם הכול ירוק - קומיט עם הודעה מסודרת

שימו לב: נתנו רצף שלם של שלבים בבקשה אחת. Claude מבצע אותם בסדר, ועוצר לאישורכם בנקודות הרגישות. זו כבר חשיבה "סוכנית" — אתם מגדירים תהליך, לא פקודות.

Pull Requests

אם מותקן אצלכם GitHub CLI (הפקודה gh) ואתם מחוברים, Claude יכול לפתוח PR בשבילכם:

תדחוף את הענף ותפתח Pull Request. בתיאור תסביר מה השתנה, למה, ואיך בדקנו

Claude יעבור על השינויים בענף, ינסח כותרת ותיאור שמסכמים אותם באמת (לא סתם "update code"), ויחזיר לכם קישור ל‑PR המוכן.

✅ גם סקירה של PR עובד גם בכיוון ההפוך: תסתכל על PR מספר 42 ותן לי סקירה — באגים אפשריים, בעיות אבטחה, והצעות שיפור. מקבלים סוקר קוד צמוד, זמין 24/7.

שחזור מטעויות

קרה משהו רע? קודם כול — לא לגעת, לשאול:

עשיתי בלגן. תראה לי מה מצב ה-git עכשיו ומה האפשרויות שלי, בלי לשנות כלום

ואז, לפי הצורך:

תבטל את כל השינויים שלא נשמרו בקומיט וחזור למצב הנקי האחרון
הקומיט האחרון היה טעות - תבטל אותו אבל תשאיר את השינויים בקבצים
⚠️ פעולות מחיקה לפעולות הרסניות (מחיקת שינויים, reset קשיח) Claude תמיד יבקש אישור מפורש ויסביר מה יימחק. קראו את ההסבר לפני שמאשרים — זו בדיוק הנקודה שבה מצב ההרשאות "הרגיל" שווה זהב.

תרגילים

תרגיל 3.1 ריפו ראשון מנוהל

קחו את אחד הפרויקטים מהפרקים הקודמים ובקשו מ‑Claude: לאתחל ריפו git, ליצור קובץ .gitignore מתאים, ולעשות קומיט ראשון. אחר כך שנו משהו קטן ובקשו "תראה לי מה השתנה ותעשה קומיט".

מה אמור לקרות

Claude יריץ git init, יזהה אילו קבצים לא שייכים לריפו (node_modules, קבצים זמניים) בשביל ה‑gitignore, ויכתוב הודעת קומיט שמתארת את התוכן. שימו לב שההודעה השנייה מתארת את השינוי, לא את הפרויקט.

תרגיל 3.2 תרגול שחזור — בכוונה

בפרויקט מהתרגיל הקודם (אחרי קומיט!), בקשו מ‑Claude "תמחק חצי מהקוד בקובץ הראשי" (כן, באמת). ואז שחזרו: "חזור למצב של הקומיט האחרון". ודאו שהכול חזר.

למה התרגיל הזה חשוב

מי שחווה פעם אחת שחזור מוצלח — מפסיק לפחד. הפחד "הסוכן יהרוס לי משהו" נעלם כשיודעים בביטחון שכל מה שאחרי קומיט הוא הפיך ב־10 שניות. זה משנה את כל צורת העבודה.

תרגיל 3.3 פיצ'ר מקצה לקצה

צרו ריפו ב‑GitHub (או השתמשו בקיים), ובצעו את התהליך המלא בבקשה אחת: ענף חדש → שינוי אמיתי → קומיט → דחיפה → Pull Request עם תיאור מלא. דרוש: gh מותקן ומחובר (gh auth login).

הצצה לפתרון

בקשה לדוגמה: תפתח ענף fix/typos, תתקן שגיאות כתיב ב-README, קומיט, דחוף, ותפתח PR עם תיאור. אם gh לא מחובר, Claude יגיד לכם ויסביר איך להתחבר — גם זו דרך ללמוד.

סיכום הפרק

  • קומיטים קטנים ותכופים = רשת ביטחון לעבודה עם סוכן
  • כל פעולות ה‑git בשפה חופשית: קומיט, ענפים, היסטוריה, PR
  • בתקלה: קודם "מה המצב ומה האפשרויות", רק אחר כך פעולה
