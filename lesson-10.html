מצב Headless ואוטומציה ב‑CI

עד עכשיו ישבתם מול Claude. בפרק הזה קמים מהכיסא: נריץ אותו כפקודה בסקריפט, נשלב אותו ב‑GitHub Actions, ונלמד לתייג @claude ב‑Pull Request — כך שהוא עובד גם כשאתם ישנים. זה הצעד הראשון לאוטונומיה אמיתית.

מה נלמד בפרק

  • מצב headless: הרצת Claude כפקודה חד־פעמית
  • שליטה בהרשאות ובפורמט הפלט משורת הפקודה
  • הרצה בטוחה ללא אישורים — בסביבה מבודדת
  • GitHub Actions ותיוג @claude

מצב Headless: הדגל ‎-p

הדגל -p (או --print) מריץ את Claude ללא ממשק אינטראקטיבי: שאלה נכנסת, תשובה יוצאת, התוכנית מסתיימת:

claude -p "כמה קבצי JS יש בפרויקט ומה הגדול ביותר?"

ומרגע שזו פקודה רגילה — אפשר לשרשר אותה כמו כל כלי Unix:

# ניתוח לוג שגיאות (macOS / Linux)
cat error.log | claude -p "מהן 3 השגיאות הנפוצות וכיצד לתקן אותן? תמצית בעברית"

# אותו ניתוח ב-Windows (PowerShell)
Get-Content error.log | claude -p "מהן 3 השגיאות הנפוצות וכיצד לתקן אותן? תמצית בעברית"

# פלט מובנה לסקריפטים (זהה בכל מערכות ההפעלה)
claude -p "רשום את כל ה-TODO בקוד" --output-format json

עם --output-format json מקבלים JSON עם התוצאה, עלות הריצה ומטא־נתונים — מושלם לעיבוד אוטומטי בהמשך ה‑pipeline.

הרשאות כשאין אדם ליד המקלדת

במצב headless אין מי שילחץ "אשר". שלוש רמות שליטה, מהעדינה לגסה:

# 1. לאשר מראש כלים ספציפיים בלבד:
claude -p "הרץ את הטסטים וסכם כשלים" --allowedTools "Bash(npm test),Read"

# 2. להגביל מספר צעדים (בלם בטיחות לכל ריצה אוטומטית):
claude -p "..." --max-turns 15

# 3. לבטל את כל האישורים - רק בסביבה מבודדת!
claude -p "תקן את כל אזהרות ה-lint" --dangerously-skip-permissions
🛑 הכלל של הדגל המסוכן ‏--dangerously-skip-permissions לגיטימי רק כשמתקיימים שלושת התנאים: (1) סביבה מבודדת — קונטיינר או VM שאין בו כלום מעבר לפרויקט; (2) בלי גישה לסודות אמיתיים; (3) התוצר עובר דרך ביקורת (PR) לפני שהוא נוגע במשהו חשוב. בדיוק כך עובדות סביבות ה‑CI שנראה עכשיו — וכך גם Claude Code on the web של Anthropic, שמריץ כל משימה בסנדבוקס מבודד. את כל שכבות ההגנה למדתם בפרק 9.

GitHub Actions: סוכן שמגיב לאירועים

הדרך המהירה לחבר את Claude לריפו שלכם ב‑GitHub היא מתוך Claude Code:

/install-github-app

ההתקנה מוסיפה workflow שמבוסס על anthropics/claude-code-action. מרגע שהוא פעיל, אפשר לתייג את Claude בכל issue או PR:

# בתגובה ל-issue:
@claude תממש את הפיצ'ר המתואר כאן ותפתח PR

# בתגובה ל-PR:
@claude יש כאן באג ב-race condition, תמצא ותקן

# סקירה אוטומטית:
@claude תעבור על השינויים ותעיר על בעיות אבטחה

‏Claude ירוץ על שרתי ה‑CI של GitHub, יבצע את המשימה, וידחוף ענף או תגובה — הכול בלי המחשב שלכם.

דוגמה: סקירה אוטומטית לכל PR חדש

.github/workflows/claude-review.ymlname: Claude Auto Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            סקור את ה-PR הזה: באגים אפשריים, בעיות אבטחה,
            וטסטים חסרים. כתוב את הסקירה כתגובה ל-PR, בעברית,
            מדורגת לפי חומרה.

מוסיפים את מפתח ה‑API כ‑Secret בהגדרות הריפו (ANTHROPIC_API_KEY) — ומעכשיו כל PR מקבל סוקר אוטומטי תוך דקות מפתיחתו.

✅ כל מה שבניתם עד עכשיו — עובד גם כאן ‏CLAUDE.md (פרק 4), פקודות ו‑Skills (פרק 5), Hooks (פרק 6), שרתי MCP בפרויקט (פרק 7) ו‑subagents (פרק 8) — כולם בתוך הריפו, ולכן הסוכן שרץ ב‑CI מקבל אותם אוטומטית. עכשיו ברור למה השקענו בתשתית: היא בדיוק מה שהופך סוכן מרוחק מ"זר" ל"חבר צוות שמכיר את הפרויקט".

תבנית לסקריפט אוטומציה מקומי

דפוס שימושי לעבודות תחזוקה תקופתיות:

nightly-deps.sh#!/bin/bash
set -e
git checkout -b chore/deps-$(date +%F)

claude -p "עדכן את התלויות המשניות (minor+patch בלבד),
הרץ את הטסטים אחרי כל עדכון, ובטל כל עדכון ששובר אותם.
סכם בקובץ DEPS_REPORT.md מה עודכן ומה נחסם ולמה" \
  --allowedTools "Bash(npm *),Edit,Read,Write" \
  --max-turns 40

git add -A && git commit -m "chore: nightly dependency updates"
git push -u origin HEAD
gh pr create --fill
nightly-deps.ps1 (Windows)$ErrorActionPreference = "Stop"
git checkout -b "chore/deps-$(Get-Date -Format 'yyyy-MM-dd')"

claude -p "עדכן את התלויות המשניות (minor+patch בלבד),
הרץ את הטסטים אחרי כל עדכון, ובטל כל עדכון ששובר אותם.
סכם בקובץ DEPS_REPORT.md מה עודכן ומה נחסם ולמה" `
  --allowedTools "Bash(npm *),Edit,Read,Write" `
  --max-turns 40

git add -A; git commit -m "chore: nightly dependency updates"
git push -u origin HEAD
gh pr create --fill

שימו לב לעקרונות: ענף נפרד, כלים מוגבלים בדיוק לצורך, תקרת צעדים, והתוצר הוא PR — לא push ל‑main. אוטומציה עם חגורות בטיחות.

תרגילים

תרגיל 9.1 headless ראשון

הריצו שלוש פקודות claude -p על פרויקט שלכם: אחת לשאלה על הקוד, אחת עם pipe של קובץ פנימה, ואחת עם --output-format json. הסתכלו על מבנה ה‑JSON שחוזר.

מה לחפש ב-JSON

שדות כמו result (התשובה), עלות הריצה ומספר הסבבים. באוטומציה אמיתית כדאי לנטר את שדה העלות — כך שומרים על תקציב ומזהים ריצות שהשתוללו.

תרגיל 9.2 סקריפט תחזוקה

כתבו סקריפט (אפשר לבקש מ‑Claude לכתוב אותו!) שרץ עם claude -p ומבצע משימת תחזוקה אמיתית בפרויקט שלכם: תיקון lint, עדכון README לפי הקוד, או הוספת JSDoc לפונקציות ציבוריות. הקפידו על --allowedTools מינימלי ו‑--max-turns.

נקודת בקרה

לפני ההרצה עשו קומיט; אחרי — git diff לביקורת. אם הסקריפט נעצר על הרשאה חסרה, הוסיפו בדיוק את הכלי שנחסם ל‑allowedTools — לא הכול. כך בונים אוטומציה בהרשאות מינימום, איטרטיבית.

תרגיל 9.3 ‏@claude בריפו אמיתי

דרוש: חשבון GitHub וריפו משלכם (מדריך ההקמה אם עוד אין). בריפו שלכם, הריצו /install-github-app והשלימו את ההגדרה. פתחו issue עם תיאור פיצ'ר קטן ומדויק, ותייגו: @claude תממש את זה ותפתח PR. סקרו את ה‑PR שנוצר — בעין ביקורתית, כאילו כתב אותו מפתח חדש בצוות.

מה אמור לקרות

תוך דקות תראו את Claude מגיב על ה‑issue עם checklist התקדמות, ובסוף — קישור ל‑PR מוכן. אם התוצאה לא מושלמת, המשיכו את הדיאלוג בתגובות ה‑PR עצמו: @claude הכפתור צריך להיות גם במובייל. זו העברת מקל מלאה לעבודה אסינכרונית.

סיכום הפרק

  • claude -p הופך את Claude לכלי שורת פקודה שאפשר לשרשר ולתזמן
  • שליטה: --allowedTools להרשאות, --max-turns לבלם, JSON לפלט מובנה
  • ביטול אישורים — רק בסביבה מבודדת, ותמיד עם ביקורת אנושית על התוצר
  • ‏GitHub Actions + ‏@claude = סוכן שעובד על הריפו בלי המחשב שלכם
