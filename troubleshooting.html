כשמשהו לא עובד

לפני שמוותרים: רוב התקלות ב‑Claude Code הן אחת מחמש, ולכולן יש תיקון קצר. העמוד הזה בנוי לפי סדר בדיקה — מתחילים מלמעלה, ועוצרים ברגע שמצאתם. שמרו אותו בסימניות; הוא יחסוך לכם ערב שלם.

סדר הבדיקה: שלוש פקודות שפותרות את רוב המקרים

אל תנחשו. שלוש הפקודות האלה אומרות לכם מה שבור, לפי הסדר הזה:

#פקודהמה היא אומרת לכם
1claude --versionהאם ההתקנה בכלל תקינה. מריצים בחלון טרמינל חדש.
2claude doctorאבחון מההרצה בטרמינל, גם כשהכלי לא מצליח לעלות: קובצי הגדרות שבורים, מצב החיפוש, בעיות הרשאה.
3/doctorבדיקה מלאה מתוך שיחה — והיא גם מציעה תיקונים ומבקשת את אישורכם לפני שהיא נוגעת במשהו.
✅ הקלף המנצח: מצב בטוח חושדים שמשהו שהוספתם שובר את זה — hook, שרת MCP, פלאגין, Skill? הריצו: 
claude --safe-mode
זה מפעיל שיחה בלי CLAUDE.md, בלי Skills, בלי פלאגינים, בלי hooks, בלי שרתי MCP ובלי פקודות מותאמות. ההתחברות, המודל והכלים המובנים עובדים רגיל. אם הבעיה נעלמה — היא אצלכם בהגדרות, ועכשיו רק צריך לצמצם איזו. זו הבדיקה הכי שימושית בכל העמוד.

1. ‏״הפקודה claude לא מזוהה״

התקלה הנפוצה ביותר, ובדרך כלל היא לא באמת בעיית התקנה — הכלי הותקן, פשוט המערכת לא יודעת איפה הוא. קודם כול, סגרו ופתחו טרמינל חדש; שינוי נתיב נטען רק בחלון חדש. עדיין לא עובד?

מוודאים שהקובץ בכלל קיים

macOS / Linuxls -la ~/.local/bin/claude
Windows (PowerShell)Test-Path "$env:USERPROFILE\.local\bin\claude.exe"

אם הקובץ לא קיים — ההתקנה לא הושלמה, חזרו לפרק 1 והריצו אותה שוב. אם הוא קיים, הבעיה היא ב‑PATH:

מוסיפים לנתיב המערכת

macOS (zsh — ברירת המחדל)echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
Linux (bash)echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
Windows (PowerShell, ואז לפתוח טרמינל חדש)$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
💡 שלוש מלכודות שכדאי להכיר (1) אם אתם עובדים בטרמינל בתוך עורך קוד — הוא יורש את הנתיב מהעורך, אז צריך לסגור ולפתוח את העורך עצמו, לא רק את הטרמינל. (2) לא בטוחים איזה shell אתם מריצים? echo $0 יגיד לכם, כדי שתערכו את הקובץ הנכון. (3) התוסף ל‑VS Code אינו מוסיף את claude לנתיב — צריך גם את ההתקנה הרגילה.

יש לכם שתי התקנות שמתנגשות?

which -a claude

אם חוזרות כמה שורות — השאירו אחת. להסרת העודפות: npm uninstall -g @anthropic-ai/claude-code, rm -rf ~/.claude/local, brew uninstall --cask claude-code או winget uninstall Anthropic.ClaudeCode, לפי איך שהתקנתם.

3. בעיות התחברות

האיפוס שפותר את רוב מקרי ההתחברות: /logout, לסגור את Claude Code לגמרי, להריץ claude ולהתחבר מחדש.

מה שאתם רואיםמה עושים
403 Request not allowedבדקו שהמנוי שלכם פעיל ב‑claude.ai/settings. אם אתם על Console — ודאו שלתפקיד שלכם יש גישה ל‑Claude Code.
This organization has been disabledכמעט תמיד: משתנה סביבה ישן ANTHROPIC_API_KEY דורס את המנוי. הריצו unset ANTHROPIC_API_KEY, ומחקו את השורה מקובץ ה‑shell שלכם. אמתו עם /status.
הדפדפן לא נפתח (SSH, WSL, קונטיינר)הקישו c כדי להעתיק את הכתובת, פתחו אותה בדפדפן המקומי, והדביקו את הקוד חזרה בטרמינל.
״זה לא נראה כמו הקוד המלא״העתיקו את הקוד כולו, כולל ה‑#, והדביקו מהר — הוא פג.
הטוקן פג שוב ושובבדקו את שעון המערכת. אימות הטוקן תלוי בו.

4. שרת MCP לא מתחבר

הפקודה /mcp מציגה את מצב כל השרתים. שלוש הסיבות הנפוצות, לפי השכיחות:

  • לא אישרתם את השרת. שרת שמוגדר ב‑.mcp.json של פרויקט דורש אישור חד־פעמי. אם סגרתם את ההודעה בטעות: claude mcp reset-project-choices, להפעיל מחדש, ולאשר.
  • נתיב יחסי. זו המלכודת הגדולה: נתיבים ב‑.mcp.json נפתרים ביחס למקום שממנו הרצתם את Claude, לא ביחס לקובץ. לסקריפטים מקומיים — השתמשו תמיד בנתיב מלא.
  • הקובץ במקום הלא נכון. הוא חייב להיקרא .mcp.json ולשבת בשורש הריפו — לא בתוך .claude/. ושרתים שתכתבו בתוך settings.json פשוט יתעלמו מהם.

השרת מחובר אבל אין ממנו כלים? בחרו Reconnect בתוך /mcp. אם זה לא עוזר, הריצו claude --debug=mcp וקראו את הלוג ב‑~/.claude/debug/.

5. ‏Hooks לא רצים, Skills לא נטענים

שתי התקלות האלה נראות מסתוריות כי הן נכשלות בשקט — אין הודעת שגיאה. הבדיקה הראשונה היא תמיד לראות אם הדבר בכלל נטען: /hooks ו‑/skills.

‏Hook שלא רץ

  • ה‑matcher חייב להיות מחרוזת, לא מערך.
  • שמות הכלים הם ב‑אות גדולה: Bash, Edit, Write, Read. "bash" לא יתפוס כלום.
  • לכמה כלים ביחד משתמשים בקו אנכי: "Edit|Write".
  • שם כלי עם שגיאת כתיב לא תואם לכלום — ובשקט.
  • ההגדרות חייבות לשבת תחת המפתח "hooks" בתוך settings.json. אין קובץ hooks נפרד.

לראות את ההערכה בזמן אמת: claude --debug, ואז להפעיל את הכלי.

‏Skill שלא נטען

  • המבנה חייב להיות .claude/skills/שם/SKILL.md — תיקייה עם קובץ בתוכה, ולא .claude/skills/שם.md.
  • ה‑description חייב להתאים לאופן שבו אתם מנסחים בקשות — זו הדרך היחידה של המודל להחליט להפעיל אותו. ראו פרק 5.
  • תג ״user-only״ ברשימה אומר ש‑Claude לא יפעיל אותו לבד. בדקו אם יש disable-model-invocation: true בכותרת.

‏CLAUDE.md שמתעלמים ממנו

הריצו /context — הוא מראה מה באמת נטען. קובץ CLAUDE.md בתת־תיקייה נטען רק כשעובדים באזור שלו. ולגבי הגדרות: settings.local.json גובר על זה של הפרויקט, שגובר על האישי.

6. איטיות, זיכרון, ותקיעות

התופעהמה עושים
איטי, או שהשיחה ״שוכחת״חלון ההקשר מלא. /compact בנקודת עצירה, /clear בין משימות, /context כדי לראות מה תופס מקום. פרק 4.
צריכת זיכרון או מעבד גבוההלהפעיל מחדש בין משימות גדולות. לבדוק אם זו תוספת שלכם עם claude --safe-mode.
הפקודה תקועה ולא מגיבהCtrl+C. אם גם זה לא — לסגור את הטרמינל ולהריץ claude --resume באותה תיקייה. השיחה נשמרת.
חיפוש איטי או חלקיהתקינו ripgrep במערכת. ב‑WSL — החזיקו את הפרויקט תחת /home/ ולא תחת /mnt/c/; זה הבדל דרמטי.

כשכלום לא עוזר

בשלב הזה כדאי לתת ל‑Claude לאבחן את עצמו: הפקודה /debug מפעילה רישום מפורט ואז מבקשת ממנו לקרוא את הלוג ולהסביר מה קרה. הלוגים יושבים ב‑~/.claude/debug/.

ואם זה נראה כמו באג אמיתי — /bug שולח דיווח ל‑Anthropic, עם מסך אישור שמראה לכם בדיוק מה נשלח לפני ששולחים.
